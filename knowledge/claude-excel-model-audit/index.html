Example workflow

Audit an existing Excel model with Claude

Trace formulas, review suspicious assumptions and produce a cell-linked exception log before changing the workbook.

Sources checked 2026-10-18Review due 2026-11-17No Sintra execution test

Replication skill · v1.0.0

Replicate this workflow

Review an existing model before an analyst-to-reviewer handoff.

Where you work
Claude for Excel
Allow for your first pilot
20–30 min first pilot; planning estimate

Bring these inputs

Workbook
Review copy with formulas, named sheets and an owner-approved output cell.
Control list
Expected totals, fiscal period, currency and known exceptions.

Start here

  1. Open the workbook in a supported Excel client, activate the existing Claude add-in and sign in.
  2. Request inspection first; select a small range so each finding can be checked.

Try a small practice case

In a disposable workbook put Revenue=100, Cost=60 and a Profit formula that incorrectly adds them.

Expected result: Flag the sign/formula issue, cite the cells and propose Revenue−Cost=40 without treating the correction as already approved.

This is a suggested acceptance case. It has not been run in Claude for Excel by Sintra.

Test the difficult cases
One formula is an intentional override
Ask the owner; do not label it an established error solely because it differs.
An external link cannot be opened
Report incomplete lineage and keep the affected check unresolved.
If it does not work
Claude has no cell citations
Narrow to a sheet/range and request the literal formula before trusting the finding.
The workbook relies on VBA or data tables
Keep those tests with their existing Excel process; record the unsupported scope.

What the sources establish

  • Claude for Excel supports workbook questions with cell citations, error tracing and model edits. It is available on eligible paid Claude plans; supported Excel builds and organization settings apply.[1]
  • Crunched describes using Claude inside its own specialist Excel review product. That customer story supports the use case, not equivalence between a generic prompt and Crunched's proprietary checks.[2]

Before you start

  • An authorized Claude for Excel add-in session and a supported Excel build.
  • A trusted review copy, agreed control totals and a named model owner.

Follow the procedure

Sintra’s suggested procedure. Validate it in your own environment.

  1. Open the existing workbook and activate the Claude add-in. Identify the version, units, periods and control cells.
  2. Ask for a workbook map and formula dependencies for one material output, with sheet and cell references.
  3. Request a read-only first pass for broken references, hard-coded overrides and inconsistent formulas. Capture an exception log.
  4. Open each cited cell and compare its formula and input lineage yourself. Distinguish an error from a legitimate policy choice.
  5. Agree specific corrections with the owner, apply them in the review copy, recalculate and compare the same controls.
  6. Save the reviewed version and exception log, keeping unresolved issues visible.

What you should get

A cell-linked exception register, reviewed corrections and before/after control totals.

How to check the result

  • Each finding resolves to an actual cell and observed formula or source.
  • Corrections preserve intended relationships and reconcile the control totals.

Try this prompt

Inspect this review copy before editing. Map the dependencies of [output cell], then return exceptions with sheet/cell, existing formula, evidence, potential impact and proposed correction. Distinguish proven errors from assumptions requiring owner judgment. Leave the workbook unchanged during the first pass. After agreed edits, recalculate and compare [control cells].
